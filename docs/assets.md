# 素材维护

## 来源到网页的关系

```text
文案集/ 或其他已记录来源
    ↓ 人工核对 / 指定导入与处理脚本
src/data/ + src/assets/ / public/
    ↓ 上传副本与清单
delivery/uploads/<批次>/
    ↓ 核实后台上传结果
官方 CDN URL + 对应资产映射
```

这条流程由明确的维护操作完成；构建不会自动导入原稿、上传文件或回填 URL。

| 位置 | 保存内容 | 修改时检查 |
| --- | --- | --- |
| `文案集/` | 原稿、原始图片、PDF、ZIP、设计资料 | 来源和科研内容；脚本是否直接读取此路径 |
| `src/assets/` | 通过 Vite 引入的本地资源与回退文件 | 静态 import、动态 glob、HTML 图板、放大链接 |
| `public/` | 按固定 URL 发布的资源 | 对外路径、游戏入口、独立播放器和附件链接 |
| `src/data/assets/` | 资产目录数据 | 本地来源、实际上传地址与调用位置 |
| `IGEM_ASSET_REGISTRY.md` | 可读的素材登记表 | 与目录数据一致；状态是否来自最近核验 |
| `delivery/uploads/` | 上传副本、映射、清单及历史核验 | 文件哈希、目标路径、实际上传状态 |

## 上传批次

从[交付索引](../delivery/README.md)进入现有上传包。新增批次放到 `delivery/uploads/<日期或明确批次名>/`。

每批至少写清用途、来源路径、后台目标目录和文件清单；需要做内容追溯时记录 SHA-256。本地移动上传包不改变官方后台层级。

上传清单中的“预期 URL”、历史探活结果和“已上传”需要区分。目录里有文件、预期地址能拼出来，均不能证明后台当前已有对应内容。完成上传后核对内容、尺寸或哈希，再更新实际 URL。

已有批次的说明和审计保留当时语境。当前状态应重新查询，避免按旧说明重复上传或覆盖同名文件。

## 资产工具

命令详情与副作用见 [scripts/README.md](../scripts/README.md)。

- `igem-asset-manager.mjs` 的扫描与更新命令可能改写资产目录或登记表；不把默认扫描当作只读检查。
- `check-cdn-links.mjs` 发起网络探测并写入本机报告；HTTP 可访问只能证明响应状态，不能证明图片内容正确。
- `prepare-*`、`import-*` 等脚本可能转换素材或覆写页面数据。先阅读输入、输出与适用批次。
- `verify-publish-assets.mjs` 检查“纯源码、无二进制素材”的发布目标；GitHub 保留原始素材，此工具不适合作为整个 GitHub 仓库的通用通过条件。

## 保留与清理

本轮保留 `文案集/`、`src/assets/`、`public/` 和游戏交付 ZIP。源码、原稿、上传副本和交付快照有不同用途，同名或同内容本身不足以决定删除。

后续如需缩小仓库，应先证明文件无运行与追溯依赖，再评估独立归档或 Git LFS 等方案。删除当前文件也不会自动缩小 Git 的历史对象。
